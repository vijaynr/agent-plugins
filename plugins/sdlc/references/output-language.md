# SDLC Output Language

## Required language

Use **ASD-STE100 Simplified Technical English** for all replies to the end user and all text that you create or change in SDLC artifacts. This is a requirement, not an optional style preference. Apply it in every phase, including questions, progress reports, errors, review findings, and final replies.

Apply the rule to artifacts produced through this plugin, even when you save them outside the plugin directory. This includes specifications, designs, plans, task lists, research notes, reports, handoffs, generated project instructions, documentation, and diagram labels.

## Writing instructions

- Use short, clear sentences. Give one instruction in each sentence.
- Use active voice. Make the responsible person or system clear.
- Use direct instructions for procedures. Put the steps in the order of use.
- Use the same word for the same meaning. Avoid idioms, jargon, and unnecessary words.
- Use approved vocabulary and grammar from ASD-STE100. Use technical names and technical verbs where the standard permits them. Define unfamiliar technical terms.
- Keep requirements, warnings, conditions, evidence, and uncertainty accurate. Do not remove necessary detail to make the text shorter.

These instructions support the standard. They do not replace its full rules and dictionary. Do not claim verified ASD-STE100 compliance unless you have checked the text against the applicable standard.

## Content that must stay exact

Preserve code, commands, paths, URLs, API names, identifiers, schema keys, required template headings, and machine-readable values. Do not change a contract or program behavior to simplify its language. Write the surrounding explanation in Simplified Technical English.

Keep exact quotations, source evidence, and externally defined text unchanged. Mark them as quotations or source text. Apply the rule to your own explanation, not to the quoted content. Do not translate existing product strings or localization data unless the task requires it.

## Delegated work

Include this language requirement and this reference in each delegated task. Apply it to supporting agents and companion-plugin work that contributes to an SDLC reply or artifact. Check the returned text before you use it. Correct text that does not follow the rule without changing its technical meaning.

## Before you send or save

1. Check each reply and each new or changed artifact section against this rule.
2. Correct unclear sentences, inconsistent terms, and unnecessary words.
3. Make sure that code, evidence, required formats, and technical meaning stay correct.
4. If you cannot verify full compliance, state the limit when relevant. Do not present a style check as certification.
